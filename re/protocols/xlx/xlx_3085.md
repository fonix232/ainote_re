# XLX 3085s Protocol

> **Status**: Verified from live Frida captures (Doway NanoRec, firmware 1.1.9, Android 13)  
> **Source app**: `com.doway.record` v3.6.0 (Dart AOT — Blutter decompiled)  
> **Test device**: Doway NanoRec, serial `IA3HA05586`, BLE name `xink_test`

## GATT Profile

All characteristics are under service `b0b0`:

| Short UUID | Full UUID                            | Role              | Properties    |
|------------|--------------------------------------|-------------------|---------------|
| `b0b0`     | `0000b0b0-0000-1000-8000-00805f9b34fb` | Primary service | —             |
| `b0b1`     | `0000b0b1-0000-1000-8000-00805f9b34fb` | CTRL TX (write) | Write         |
| `b0b2`     | `0000b0b2-0000-1000-8000-00805f9b34fb` | CTRL RX (notify)| Notify        |
| `b0b3`     | `0000b0b3-0000-1000-8000-00805f9b34fb` | Audio live      | Notify        |
| `b0b4`     | `0000b0b4-0000-1000-8000-00805f9b34fb` | File data       | Notify        |
| `c0c0`     | `0000c0c0-0000-1000-8000-00805f9b34fb` | OTA service     | —             |

OTA characteristics use long-form UUIDs:
- TX: `e49a25e0-f69a-11e8-8eb2-f2801f1b9fd1`
- RX: `e49a28e1-f69a-11e8-8eb2-f2801f1b9fd1`

**Device identification**: advertises `b0b0` service *without* `0011200a-...` (that UUID exclusively marks a 2837 device).

## Frame Format

### TX (host → device, b0b1)

```
[A0] [0A] [01] [cmd:1] [len:1] [payload...] [crc_lo] [crc_hi]
```

- Preamble `A0 0A` is fixed — Dart field `BleOperateManager.field_2b = false` selects this path
- `len` = payload byte count (1 byte)
- CRC-16/ARC appended little-endian

> **Sub-variants**: The Dart app contains two distinct implementations keyed by `field_2b`. When `false` (3085s): preamble `A0 0A`. When `true` (separate variant): preamble `E5 5E`. These are **not** interchangeable on the same device — `E5 5E` frames belong to a different hardware sub-variant.

### RX (device → host, b0b2 notify)

```
[A0] [0A] [category:1] [opcode:1] [len:1] [payload...] [crc_lo] [crc_hi]
```

- Preamble `A0 0A` (mirrors TX — 3085s sub-variant)
- `category` (byte 2): consumed but not used for dispatch
- `opcode` (byte 3): dispatch key
- `payload`: bytes `[5 .. 5+len-1]`
- CRC-16/ARC at the end (LE)

### CRC-16/ARC

Polynomial `0xA001`, reflected, init `0x0000`. Covers all bytes before the two CRC bytes.

```
crc = 0
for each byte b:
    crc ^= b
    for i in 0..7:
        if crc & 1: crc = (crc >> 1) ^ 0xA001
        else:       crc = crc >> 1
```

## Connect Handshake

Verified from Frida captures (both first-time bind and reconnect).

```
Host                          Device
 ──  TX 0x02 getBindInfo  ──►
 ◄──  RX 0x02 response     ──
         payload = [00]          ← NOT bound (1 byte, value 0)
         payload = [17 bytes]    ← already bound (17-byte token)
 ──  TX 0x03 bindDevice   ──►
         17-byte token:
           • unbound  → 17 × 0x00
           • bound    → echo the 17 bytes from step 2
 ──  TX 0x01 getSerial    ──►
 ◄──  RX 0x01 response     ──
         payload = ASCII serial string (e.g. "IA3HA05586", 10 chars)
```

- No Doway cloud server is involved in the bind flow
- The serial string (not a MAC) is used as a stable settings key in persistent storage
- After the handshake the host sends `syncTime (0x04)` and `getDeviceInfo (0x05)` / `platformSet (0x18)`

## Opcode Table

### Information & Setup

| Opcode | Name            | TX payload              | RX payload (on ACK)                   |
|--------|-----------------|-------------------------|---------------------------------------|
| `0x01` | getSerial       | empty                   | ASCII serial string (null-terminated) |
| `0x02` | getBindInfo     | empty                   | `[00]` = unbound; `[17 bytes]` = bound token |
| `0x03` | bindDevice      | 17-byte token (see [Connect Handshake](#connect-handshake)) | `[status:1]`                 |
| `0x04` | syncTime        | 6-byte binary (see [SyncTime](#synctime-0x04-tx)) | empty ACK                           |

| `0x18` | platformSet     | `[00]` = Android, `[01]` = iOS | `[status:1]`               |

### Recording

| Opcode | Name            | TX payload | RX payload                                         |
|--------|-----------------|------------|----------------------------------------------------|
| `0x06` | startRecord     | empty      | `[status:1][filename:14][recMode:1]`              |
| `0x07` | stopRecord      | empty      | `[status:1][filename:14][00][00][fileBytes:2 BE][01][00]` |
| `0x08` | pauseRecord     | empty      | `[status:1]`                                       |
| `0x09` | resumeRecord    | empty      | `[status:1]`                                       |
| `0x15` | getRecordInfo   | empty      | `[status:1][filename:14][00][00][fileBytes:2 BE][01]` |

- `filename`: 14 ASCII chars, `YYYYMMDDHHMMSS` timestamp of recording start
- `recMode`: `01` = note mode, `02` = call mode (hardware button state, read-only from app)
- `fileBytes`: running file size in bytes (2-byte BE); not a duration — reflects bytes written so far

### File Management

| Opcode | Name          | TX payload                     | RX payload                                 |
|--------|---------------|--------------------------------|--------------------------------------------|
| `0x0A` | getFiles      | empty                          | Multiple frames (see [File List](#file-list-0x0a-rx)); sentinel = 1-byte frame |
| `0x0B` | startSyncFile | filename ASCII + 4-byte offset | ACK1: `[00][size:4 BE]`; ACK2 (done): `[err≠0]` |
| `0x0C` | endSyncFile   | empty                          | `[status:1]` — device finished sending     |
| `0x0D` | deleteFile    | filename ASCII                 | `[00]` = OK, `[non-zero]` = failed         |

**File data** arrives on `b0b4` as raw chunks (no framing header).

## Payload Formats

### SyncTime (0x04 TX)

6 binary bytes — not ASCII:

| Byte | Field   | Encoding          |
|------|---------|-------------------|
| [0]  | year    | `year - 2000`     |
| [1]  | month   | 1–12              |
| [2]  | day     | 1–31              |
| [3]  | hour    | 0–23              |
| [4]  | minute  | 0–59              |
| [5]  | second  | 0–59              |

### DeviceInfo (0x05 RX payload)

Payload is 49+ bytes. All multi-byte integers are big-endian.

| Bytes   | Field       | Notes                                                    |
|---------|-------------|----------------------------------------------------------|
| [0–3]   | storageTotal | **MiB** (raw uint32 BE — direct MiB value, not sectors) |
| [4–7]   | storageFree  | **MiB** (raw uint32 BE)                                 |
| [8]     | batterySt   | Charging status (`0` = not charging, `1` = charging)    |
| [9]     | battery     | Battery % (0–100)                                       |
| [10]    | recordSt    | `0` = idle, `1` = active                                |
| [11]    | ver_h       | Firmware major (×100 in final string)                   |
| [12]    | ver_m       | Firmware minor (×10)                                    |
| [13]    | ver_l       | Firmware patch                                          |
| [14]    | usb         | `0` = charge, `1` = disk                               |
| [15]    | mode        | Device mode                                              |
| [16]    | lightSt     | Always `0xFF` — **not** the screen toggle               |
| [17–37] | deviceName  | 21-byte null-padded ASCII string                         |
| [38]    | unknown     | field `?[43]` in Frida output — purpose unknown          |
| [39]    | noise       | See [Setting Values](#setting-values)                    |
| [40]    | vox         | `0` = off, `1` = on                                     |
| [41]    | recordTime  | Max recording duration index (see [Setting Values](#setting-values)) |
| [42]    | screen      | `0x00` = auto-off, `0xFF` = always-on (screen toggle)   |
| [43]    | motor       | `0` = off, `1` = on                                     |
| [44–46] | wifiVer     | Wi-Fi firmware version (h, m, l bytes)                  |
| [47–49] | unknown     | fields `field_53`, `field_5b`, `field_63`               |

> **Trap**: `lightSt` at `[16]` is always `0xFF` — the screen toggle is at `[42]` (confirmed by Frida frame index `[47]` = payload `[42]`). `ledLight` is **not** present in the 0x05 payload; it arrives only via `0x0F` statusPush. See [Frida Byte Indices](#frida-byte-indices) below.

### StatusPush (0x0F RX, unsolicited)

20-byte snapshot, sent periodically and after any setting change:

| Byte | Field      | Values                                        |
|------|------------|-----------------------------------------------|
| [0]  | batterySt  | `0` = not charging, `1` = charging            |
| [1]  | battery    | Battery % (0–100)                             |
| [2]  | recordSt   | `0` = idle, `1` = active                      |
| [3]  | recMode    | `1` = note, `2` = call (hardware button — read-only) |
| [4]  | vox        | `0` = off, `1` = on                           |
| [5]  | noise      | `0x00`/`0x05`/`0x09`/`0x0F` (see [Setting Values](#setting-values)) |
| [6]  | mode       | Device mode                                   |
| [7]  | screen     | `0x00` = auto-off, `0xFF` = always-on         |
| [8]  | recordTime | Max recording duration index (see [Setting Values](#setting-values)) |
| [9]  | ledLight   | `0` = off, `1` = on                           |
| [10] | motor      | `0` = off, `1` = on                           |
| [11–19] | reserved | —                                           |

### File List (0x0A RX)

The device sends one frame per file, followed by a 1-byte sentinel frame.

**File entry frame payload** (observed format):

```
[00] [filename: up to 14 ASCII chars] [00] [size: 4B LE] [2B unknown]
```

**Sentinel**: payload length = 1 (signals end of list).

### Recording ACKs (0x06 / 0x07 / 0x15)

**startRecord ACK (0x06)** — 16-byte payload:

```
[status:1] [filename: 14 ASCII chars = YYYYMMDDHHMMSS] [recMode:1]
```

**stopRecord ACK (0x07)** — 21-byte payload:

```
[status:1] [filename: 14 ASCII chars] [00] [00] [fileBytes: 2B BE] [01] [00]
```

**getRecordInfo (0x15)** — 20-byte payload:

```
[status:1] [filename: 14 ASCII chars] [00] [00] [fileBytes: 2B BE] [01]
```

`fileBytes` is the running file size in bytes at the time of the request — **not a duration field**.

## Audio Channels

### Live recording (b0b3)

- Codec: **MP3** (MPEG Version 2, Layer III) — confirmed from Frida capture; sync word `FF F3` appears at the start of every MPEG audio frame
- Parameters (from frame header `FF F3 48 C4`): **32 kbps, 16 kHz, mono, no CRC**
- MP3 frames are 288 bytes; they span multiple BLE notifies (MTU ~182 bytes), so `FF F3` appears mid-notify
- Streamed continuously while the device is recording

> Note: the TS class had an incorrect `audioCodec = SBC` assignment in the handshake — removed.

### File download (b0b4)

- Codec: **MP3** (MPEG Version 2, Layer III) — confirmed from Frida capture; `ff f3 48 c4` sync word appears at offset 108 of the first chunk, identical to the b0b3 live stream
- Parameters: **32 kbps, 16 kHz, mono** — same as live stream
- No container or file header — raw MP3 stream; the first chunk may begin mid-frame (continuous encoding, file starts wherever the encoder was when recording began)
- Triggered by `startSyncFile (0x0B)` on b0b1; data arrives on b0b4
- Completion signalled by `endSyncFile (0x0C)` on b0b2, or second `0x0B` ACK with `err ≠ 0`

## Frida Byte Indices

The Frida script logs payload bytes using absolute **frame** offsets (frame[5] = payload[0]).  
The `0x05` Frida output uses these frame-relative indices (add 5 to get payload-relative):

```
storage[5-12]   = payload[0-7]   storageTotal / storageFree (4B BE each, value is MiB)
batterySt[13]   = payload[8]
batt[14]        = payload[9]     battery %
rec[15]         = payload[10]    recordSt
ver[16-18]      = payload[11-13] firmware version
usb[19]         = payload[14]
mode[20]        = payload[15]
lightSt[21]     = payload[16]    always 0xFF
name[22-42]     = payload[17-37] deviceName (21 chars)
?[43]           = payload[38]    unknown
noise[44]       = payload[39]
vox[45]         = payload[40]
recTime[46]     = payload[41]
screen[47]      = payload[42]    ← screen toggle (NOT lightSt at [16])
motor[48]       = payload[43]
```

> **Storage encoding**: `storageTotal` and `storageFree` hold the raw MiB count directly (e.g. `0x00003A98` = 15000 MiB ≈ 14.6 GiB). Earlier analysis assumed 512-byte sector counts, which produced values ~2048× too small. Confirmed by comparing the reported value against the device's labelled capacity (64 GiB card).
